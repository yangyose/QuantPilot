# `is_suspended` 缺陷影响评估（2026-09-02）

> 触发：追查「两只持仓在候选池中无评分」（600664.SH / 600722.SH），一路查到 universe 构造。
> 状态：**已定位、未修复**。本文只做评估，不含修复动作。
> 严重度：**高**——影响每一天的选股范围，且自 Initial commit 起持续至今。

---

## 1. 结论摘要

`TushareAdapter.fetch_daily_quotes` 调用停牌接口时**参数名写错**，Tushare 静默忽略该参数并
返回全表最早的 5000 行（1999-2001 年的停牌记录）。系统把这批 1999 年的代码当成「今天停牌」，
每日固定排除约 **818 只**实际正常交易的股票。

**五年 666 万行行情数据中，`is_suspended = true` 共 110 万行，其中成交额 > 0 的占 100%，
成交额为 0 的占 0%。** 即该标记的假阳性率 100%、真阳性率 0——它从未正确识别过一次停牌。

---

## 2. 缺陷本体

### 2.1 主缺陷：参数名错误（`backend/src/quantpilot/data/adapters/tushare.py:146`）

```python
self._call(self._pro.suspend_d, suspend_date=date_str)   # ❌ 无此参数
#                               ^^^^^^^^^^^^ 正确为 trade_date
```

生产实测（2026-09-02，容器内直调）：

| 调用 | 行数 | 去重代码 | 返回的 trade_date 范围 |
|---|---|---|---|
| `suspend_date=`（现网） | 5000 | **1008** | **19990504 ~ 20010221** |
| `trade_date=`（正确） | **8** | 8 | 20260902 |

这是 `CLAUDE.md §4.11`「接了但没生效」族的又一例，载体为**外部接口参数名**——
与 §4.4 的 pandas_ta `bbands(std=)` 形态完全一致：参数落进被忽略的位置，
不报错、无告警、测试全绿。

### 2.2 次缺陷：未按 `suspend_type` 过滤

`suspend_d` 返回含 `suspend_type`：`S` = 停牌、`R` = **复牌**。现代码取全部行，
不加区分。2026-09-02 正确调用的 8 行中即有 1 行为 `R`。

修主缺陷后若不修这条，复牌股会被当成停牌。

### 4.1 漏检方向：实际零损害

## 5. 修复方案与风险

### 5.1 代码修复（2 行）

```python
# tushare.py:146
self._call(self._pro.suspend_d, trade_date=date_str)          # 参数名
# 并在合并处按 suspend_type 过滤
suspended_codes = set(suspend.loc[suspend["suspend_type"] == "S", "ts_code"])
```

判据（按 §4.11「外部接口是否真返数」）：**不能只断言「不抛异常」**。须钉
「同一天正确调用返回的 `trade_date` 全部等于入参日期」+「返回行数与全市场规模不同量级」。

### 5.2 历史数据回补：可证明安全

```sql
UPDATE daily_quote SET is_suspended = false WHERE is_suspended;
```

**这条 UPDATE 是可证明正确的**：110 万条被标行中，成交额 > 0 的占 100%、为 0 的占 0 条——
**有成交即未停牌**，无一例外。故全量置 false 不会误改任何一行真实停牌记录（本就一条都没有）。

影响行数 1,103,596 / 6,662,108。按 C-1 属破坏性写操作，须单独确认 +
`pg_dump --data-only -t daily_quote` 精确回滚点 + 执行后查行数实证。

### 5.3 修复的风险（这才是难点）

修复**不是纯收益**，它会改变生产行为：

1. **评分结果整体变化**——universe +17%，横截面分位全部重算，买入清单会明显不同
2. **ICIR 权重需重新收敛**——当前权重在旧 universe 上拟合，扩容后需要时间重新稳定
3. **与 C1 观察期重叠**——C1 刚上生产 3 个交易日（观察期今日收口）。若立刻叠加一个
   影响面更大的变更，**两者效果将无法归因**
4. **历史 IC / ICIR 全部基于旧 universe**——修复后新旧数据不可直接拼接比较

## 6. 与 V1.5-K 的次序关系（关键）

V1.5-K 的立项前提是「**先修尺子，再量东西**」，计划做一次全 5y、约 13h 的面板重跑。

**若在修复本缺陷前重跑，那次重跑会把 15% 的系统性缺失固化进「用来判断别的东西对不对」
的基准数据里**——而 K 产出的正是「自己错了没有更上层的尺子能发现」的度量。

故次序应为：**修复 `is_suspended` → 历史回补 → 再跑 K 的全 5y 面板**。

否则 13h 的重跑要么作废重来，要么得到一把有系统性偏倚的尺子。

4. **同类排查：已完成（2026-09-02），结论是孤例。**
   对 adapter 中 **11 个**带日期参数的接口逐个生产实测，判据为
   **「返回数据的日期是否落在入参窗口内」**（不是「有没有报错」——**11 个全都不报错，坏的那个也不报错**）：

   | 接口 | 结果 |
