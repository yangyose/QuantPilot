# F-5「非连续亏损」过滤：实现不符规范，但按规范改正会更差

> 2026-09-10 · 只读 5434（`v1.5k-clean-5y` 同一份已修前视偏差的数据）
> 开发集（≤2025-07-31，K-7 纪律）· 本文**不含任何代码改动**

## 0. 为什么查它

`universe_daily_stat`（alembic 0027）上线后第一次跑真实数据就照出：
**F-5 一条剔掉全市场 35~44%**，是选股面的绝对主导项，而此前无人量过
（CLAUDE.md §6 已记）。选股面的第一道闸门比任何因子权重都更能决定用户买到什么，
所以先量它。

## 1. 实现与规范不符：漏掉了「亏损」这一半

**SDD 第 261 行**（universe 过滤表）：

> 排除连续两个报告期**净利润亏损**且**无改善趋势** ｜ 净利润同比增速仍为负值；
> 非 ST 但基本面极差的标的（可配置开关）

规则是一个**合取**：①连续两期净利润**亏损** ②**且**无改善趋势（= 同比增速仍为负）。
右侧那一列解释的是 ②，不是整条规则。

**实现**（`engine/universe.py::_is_consistently_losing`）只判 ②：

```python
# F-5：非连续亏损（net_profit_yoy < 0 为亏损，NaN → 跳过）
```

⚠️ 注释里那句「`net_profit_yoy < 0` 为亏损」是**错的**：
`net_profit_yoy` 是**净利润同比增长率**，不是利润额。实测该字段
（2025-12-31 期）分位：min −416.18 / p25 −0.26 / 中位 **0.04** / p75 0.41 / max 88.13
——是个小数形式的增长率。`< 0` 的含义是「利润同比**下滑**」，
而不是「公司**亏了钱**」。一家盈利但增速放缓的公司会被判为「亏损」。

**规模差异**（2025-12-31，取最近两个有值报告期，与代码同口径，n=5505）：

| 口径 | 剔除比例 |
|---|---|
| **现行**：两期同比增速 < 0 | **37.2%** |
| **规范**：两期真亏损（`eps < 0`）**且**同比 < 0 | **10.5%** |
| **差额 = 被误剔**：两期都盈利、只是增速下滑 | **26.7%**（≈1470 只）|

37.2% 与生产观测的 35~44% 吻合，可确认这就是那 35~44% 的来源。

> **一个减轻情节**：`eps` 是 C2 于 2026-09-09 才回填进 `financial_data` 的
> （alembic 0028）。在此之前库里**没有任何利润额字段**，只有 `net_profit_yoy`——
> 所以当初用它做代理是「手上只有这个」，不是疏忽。**是 C2 的回填才第一次
> 让「按规范实现 F-5」成为可能。**

## 2. 但按规范改正会更差——规范的经济假设在本样本上不成立

分三组（PIT：只用 as_of 当日已公告的行），42 个月度锚点日、h=20 交易日、
采样间隔 ≈21 交易日故**前瞻窗口互不重叠**（朴素 t 有效）：

- **A 规范剔除组**：两期真亏损且同比 < 0 —— SDD 要剔的就是这批
- **B 误剔组**：两期都盈利、只是增速下滑 —— 现行实现多剔的那批
- **C 保留组**：现行 F-5 之后留下的

| 口径 | 月均 20 日收益 % | t |
|---|---|---|
| **A 规范剔除组（真亏损）** | **+1.766** | 1.10 |
| B 误剔组（盈利但降速） | +1.191 | 0.92 |
| C 保留组（现行 F-5 之后） | +1.146 | 0.93 |
| A∪B = 现行 F-5 剔除的整体 | +1.328 | 0.96 |

配对差值（**>0 = 剔除这批有利**）：

| 差值 | 均值 | t | >0 占比 |
|---|---|---|---|
| **C − (A∪B)：现行 F-5 的净效果** | **−0.181** | −0.77 | 40.5% |
| **C − A：若按规范只剔真亏损** | **−0.620** | −1.23 | 35.7% |
| C − B：只剔盈利降速组 | −0.044 | −0.26 | 47.6% |
| A − B：真亏损 减 盈利降速 | +0.575 | 1.41 | 69.0% |

### 三条结论

1. **现行 F-5 没有可测收益，点估计还是负的**：它剔掉 37% 的市场，
   而被剔掉的那批月均收益 **高于**保留的（净效果 −0.181%/月），
   只有 40.5% 的月份对它有利。不显著（t=−0.77），但也**完全没有正向证据**。

2. **按 SDD 规范修正会更差**：净效果 −0.620%（t=−1.23，仅 35.7% 月份有利）。
   原因直白——规范专门要剔的「真亏损」组在本样本上表现**最好**（+1.766%）。
   这是 A 股常见的低价亏损股投机性反弹，与规范隐含的假设
   「亏损公司会继续跑输」相反。

3. 于是本条的处境很特殊：**「实现不符规范」这个判断成立，但「按规范改正」
   是错的方向。** 两边都不该动——照规范改会主动变差，凭这组不显著的数字
   放宽或删除 F-5 同样是拟合开发集（今天已在 F-Score 门控与 `roe_quality`
   上各吃过一次，见 `scoring_monotonicity_2026-09-10.md` §7/§10）。

## 3. 必须声明的口径局限

- **A 组大概率偏小盘低价股**，其 +1.766% 有相当部分是规模/低价效应，
  **不等于「应该买它们」**：真实可交易性受流动性限制，而 universe 的
  F-7 成交额阈值本就会挡掉一部分。本文没有做规模中性化。
- 本文的分组**未排除金融股**，而代码里 F-4/F-5/F-6 对金融股是豁免的。
  金融股占比小（约 119/3200），不改变方向，但绝对数字会有微小偏差。
- 42 个锚点、全部 |t| < 1.5，**没有一项显著**。
- 开发集内的事后检验，不是样本外证明。

## 4. 处置：只登记，不动代码

- **不按规范修正** F-5（会主动变差）
- **不放宽/不删除** F-5（证据不显著，改了就是拟合开发集）
- 但**必须把这个矛盾登记进权威源**：SDD 第 261 行那条规则的经济假设
  在本仓数据上不成立，而实现恰好偏离了规范、方向上略优于规范。
  这不是「实现有 bug 待修」，是「规范这条本身需要重新论证」——
  按 C-5，改规范要先回写 SDD，而回写的前提是 holdout 验证。
- ⚠️ **代码注释里那句「`net_profit_yoy < 0` 为亏损」是事实错误，应当就地订正**
  （字段是增长率）——这一条与是否改变过滤行为无关，纯属把话写对，
  否则下一个人会照着这句话继续推理。

**若将来要动 F-5，需要的证据**：holdout（2025-08~2026-07）上复现
「放宽 F-5 后头部组合收益不变差」，且做规模中性化后 A 组的优势仍然存在。
潜在收益是可选池由剔除 37% 降到 10.5%（选股面扩大约四分之一），
量级不小，但**目前没有任何显著证据支持这么做**。

## F-3 / F-8：1115 天恒为 0 —— 按元判据查，确实是「结构性永不命中」

CLAUDE.md §4.11 元判据：*机制若设计上应当生效，就去查它生效时会留下的痕迹；
查不到痕迹 = 没生效*。这两条 1115 天零痕迹，逐个查证如下。

**F-3 非停牌**（`mask &= ~stock_info["is_suspended"]`）：
`is_suspended` 在 `daily_quote` 上，而**全停牌的股票当天根本没有 `daily_quote` 行**
（Tushare `daily` 不返回未交易的股票）。实测 6.04M 行 `is_suspended` **全为 False**、
`vol = 0` 的行**一行也没有**。所以该列恒 False，F-3 结构性永不命中。
⚠️ 别把这解读成「2026-09-03 那次 `suspend_d` 修复没生效」——恰恰相反：
修复前是**错误地**把 818 只正常股标成停牌（那些股票有行情行，故标记写得上去）；
修好之后，真停牌的股票压根没有行情行可标，于是全 False。**两种全 False 的成因相反。**

**F-8 涨停封死**（`limit_up & (vol == 0)`）：判据与现实不相容——
**涨停封死的股票仍然有成交量**（有人买到了，只是买不到更多），实测日均
36~73 只涨停股中 `vol = 0` 的恒为 **0.00**。意图（涨停买不进 → 别推荐）成立，
判据选错了。

## 但影响实测为零：意图由 `signal.py:321` 承担

| 检查 | 实测 |
|---|---|
| 在市但当日无行情行的股票 | 1~22 只/日 |
| ↳ 其中进了候选池 | **0** |
| 候选池里当日涨停的行 | 609 / 76494（0.80%），其中在池 367 |
| ↳ **收到 BUY 信号的** | **0 / 5285** |

原因是 `engine/signal.py:321` 有一道**下游护栏**：

```python
if is_suspended or limit_up:
    continue
```

买入可行性这件事本该在**发信号的那一刻**判定（那才是用户真要下单的时点），
所以护栏放在这里比放在 universe 更合理。F-3/F-8 属**冗余**，不属失效。

## 处置：不动，但必须把这层依赖写下来

- **不要「修复」F-3 / F-8**：它们没有造成任何损害，而改动会实质改变 universe 组成
  （F-8 若改判据为 `limit_up`，每天多剔 36~73 只）——那是一次无证据的选股变更。
- 🔴 **但必须知道：这道保护现在只存在于 `signal.py:321` 一处。**
  谁要是哪天觉得「universe 层的 F-3/F-8 已经管了」而删掉那一行，
  保护会**完全消失**且不报错——而 F-3/F-8 其实从来没管过。
  已在 `universe.py` 两条规则处就地标注这层依赖关系。
