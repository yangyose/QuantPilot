# 🔴 历史财务数据存在前视偏差（look-ahead bias）

> 2026-09-07 · 数据源：本地算力中心 5434 **与生产库**（两边逐条比对，结果一致）
> 发现路径：实施 `universe_daily_stat` → 看到 F-5 剔除数异常 → 追查为何
> 2026-08-25 与 2025-08-25 同为 8 月下旬却相差 60 倍
> **状态：仅调查，未改代码、未改数据。修复方案待拍板。**

## 1. 现象

`financial_data` 的日频快照行约定是 `publish_date = 交易日`，本应携带
**该交易日当时已知**的基本面。实测发现：历史行携带的是**事后才公布**的数值。

取每个报告期结束后约两周的一个交易日（当时该期对绝大多数公司尚未披露），
把该日行上的 `net_profit_yoy` 与**该期最终公布值**逐股比对：

| report_period | 取样交易日 | 行数 | `yoy` 非空 | **等于最终公布值** |
|---|---|---|---|---|
| 2024-06-30 | 2024-07-15 | 5343 | 5343 | **5323** |
| 2025-06-30 | 2025-07-15 | 5408 | 5391 | **5384** |
| 2025-09-30 | 2025-10-15 | 5425 | 5416 | **5415** |
| 2025-12-31 | 2026-01-15 | 5457 | 5440 | **5438** |
| 2026-03-31 | 2026-04-15 | 5494 | 5473 | **5470** |
| **2026-06-30** | **2026-07-15** | 5506 | **695（12.6%）** | — |

`roe` 同样泄漏（2024-06-30 期：5296/5343）。

### 1.1 不是「沿用上期」的误标

2025-06-30 那一行里，7 月 15 日的值**等于上一期（2025-03-31）**的只有 **2 只**，
而**等于本期最终值**的有 5384 只，严格泄漏（非空 ∧ ≠Q1 ∧ =Q2 最终）**5349 只**。
即确实把未来值提前写了进去，而非把旧值贴上新期标签。

### 1.2 生产库同样如此，但**实时路径干净**

同一探针在生产库上执行（只读）：

| 库 | 2025-06-30 @ 2025-07-15 | 2026-06-30 @ 2026-07-15 |
|---|---|---|
| 5434 副本 | 5391 非空 / 5384 = 最终值 | 大量 NULL |
| **生产** | **5391 非空 / 5384 = 最终值** | **5525 行，非空 0** |

即污染在**回填的历史**里、两库皆有；而 2026-07 起的**实时每日采集是干净的**
（2026-07-15 那天没有任何一只股票已有 2026 半年报数据——这正是正确的 PIT 行为）。

**因此：当前与今后的实盘决策用的是干净数据，受影响的只有历史分析与回测。**
这不降低本条的严重性（它使全部历史结论存疑），但把影响面限定住了。

### 1.3 污染边界

至少延伸到 **2026-04**；只有 **2026-07 起**（生产实时每日采集）的行是干净的
（未披露期为 NULL）。**整个面板窗口 2021-11-23 ~ 2026-06-30 基本全在污染区内。**

## 2. 成因（待代码侧确认）

两条采集路径对 `publish_date` 的语义不同：

| 路径 | `publish_date` 语义 |
|---|---|
| `fetch_financial_by_stock`（TD-1 逐股 `fina_indicator`）| **`ann_date`（公告日）** |
| `fetch_financial_data`（日频快照）| **交易日** |

历史回填在**回填当时**调用日频快照路径，把当时已知的基本面写到了每个历史交易日的行上。
于是「2024-07-15 这一行」携带的是**回填那天**已知的 2024 半年报数据。

### 2.1 同族排查：范围比初判窄，只有日频快照那条路径

按「哪些字段经哪条路径入库」逐个验，两条**干净**：

| 字段 | 来源路径 | `publish_date` 语义 | 历史是否前视 |
|---|---|---|---|
| `total_equity` | `fetch_balance_sheet` | `ann_date` | **干净** |
| `is_st` | `namechange`（PIT 逻辑，§4.3）| — | **干净** |
| `net_profit_yoy` / `roe` / `revenue_yoy` / `debt_to_asset` | **日频快照** `fetch_financial_data` | **交易日** | **污染** |

证据：
- `total_equity` 锚点行的 `publish_date` 落在真实披露季（2025-06-30 期中位
  **2025-08-27**、2025-12-31 期中位 **2026-04-23**、2026-03-31 期中位 **2026-04-28**），
  与法定披露窗口吻合 → 用的是公告日。
- `is_st`：2022 年起有过 ST 的 670 只中，**全程为 ST 的仅 5 只**、中途变化 665 只。
  若按「今天是不是 ST」回填，应大量表现为「全程 ST」。

**故 F-4（用 `total_equity`）不受影响，F-5（用 `net_profit_yoy`）受影响。**
这也解释了为什么当日两个修复的性质不同。

## 3. 影响

### 3.1 两条路径，第二条更要命

1. **价值策略的 `roe` 分量**直接取到泄漏值。
2. **universe 本身是用泄漏数据筛出来的**——F-5 用 `net_profit_yoy`、F-4 用
   `total_equity`。即历史上每一天，系统都在用「尚未公布的财报」提前剔除亏损股。
   **输家被带着后见之明拿掉了**，这会系统性抬高其后所有度量，
   且抬高的是**基线**而非某个因子，因而不会表现为「某因子异常好」。

### 3.2 受影响的产出

- C1 面板（`ic_baseline_pre_c1` 与 off/on 两组）
- V1.5-K 两批面板（`v1.5k-full-5y`、`v1.5k-full-5y-r2`）
- 全部历史回测与历史日级 IC

**V1.5-K 的立项前提是「先修尺子，再量东西」——本条说明尺子本身漏了。**

### 3.3 不受影响的

- 纯价格因子的**计算**（momentum / trend / mean_reversion 的因子值本身）
- **同一份污染数据内部的相对比较**（如 C1 的 off/on 两组同口径对照）
- **实时路径**：2026-07 起的生产每日管线用的是干净数据

⚠️ 但「相对比较不受影响」有前提：两组的 universe 必须相同。若一次改动同时
改变了 universe（如 F-5 修复），则该对比跨了口径，见
`universe_filter_composition_2026-09-07.md` §5。

## 4. 与当日另外两处修复的关系

- **F-4 / F-5 修复不受本条影响、也不应因本条推迟**：它们修的是**实时**数据路径上的
  真实缺陷，而实时数据恰恰是干净的那一部分。F-5 之所以在 2026-08 才暴露，
  正是因为**只有实时数据才有未披露期的 NULL 占位行**——
  历史数据用前视值把这个洞填上了，于是缺陷在历史上不可见。
- 换言之：**前视偏差一直在替 F-5 缺陷打掩护**。两者是同一件事的两面。

## 5. 处置（待拍板，本文不动任何东西）

修复不是改查询能了事——需要按 `ann_date` 重建历史采集，使每个历史交易日的行
只携带**该日已公布**的信息。属 CLAUDE.md §5.4 的「跨 phase 大重构」+「物理资源约束」
（5y 重灌，历史实测 12~50h）。

待决：

1. 是否重建历史？重建后所有历史 IC / 回测结论都要重算。
2. 若暂不重建，**已产出的面板结论如何定性**——建议至少标注
   「绝对水平含前视偏差，不可外推到生产」，而**相对比较**在同口径下仍可用。
3. 是否先加一条**廉价的检测**：对任一历史日抽查「未披露期的行是否已有值」，
   把这个性质变成可持续观测的量，而不是靠一次性调查。

⚠️ 在 1 未完成之前，**任何「历史上这个策略有效」的结论都应视为未经证实**。
