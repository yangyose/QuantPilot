## 0. 摘要

系统的主要风险**不在算法精度，而在大量代码路径从未被真实数据走过**。本次查到的三处
退出缺陷、以及此前审计的 12 个零引用配置字段、5 例静默忽略，属于**同一族失败**：
接了参数 / 写了规则 / 留了默认值，于是静默失效、不报错。

按离钱的距离排序：

| 优先级 | 问题 | 状态 |
|---|---|---|
| **P0** | **信号周期（20 交易日）与持仓周期（40~72 交易日）错配**——买入依据早已失效仍持有，alpha 在持有期内衰减光，从未兑现（§1.7）| 已实证 |
| **P0** | 退出链路四处缺陷叠加 → 实际只剩 −8% 硬止损，且它也失效 | 已实证 |
| **P0** | 信号 → 成交无关联记录，系统无法知道自己的建议是否有用 | 已实证 |
| **P1** | 仓位固定比例，不随信心度/波动率标定 | 已实证 |
| **P1** | 回测保真度缺口 + 生产上几乎从未跑过 | 已实证 |
| **P2** | 风控无相关性聚集检查；换手与成本从未度量 | 已实证 |

> **关于「修好退出就能赚钱吗」**：不能。退出域修复是**止血**（−40% 变 −8%）与
> **周期错配修复的前置**，本身不产生 alpha。真正的盈利杠杆见 §9.0。

## 1. 退出链路（P0）

### 1.1 现象

持仓四只全部亏损超过 `stop_loss_pct = 8%`，全部未产生卖出信号：

| 股票 | 浮亏 | 建仓日 | 在最新候选池 |
|---|---|---|---|
| 603063.SH | **−40.67%** | 2026-06-26 | ✗ |
| 601138.SH | −15.23% | 2026-05-14 | ✗ |
| 002384.SZ | −13.14% | 2026-05-22 | ✗ |
| 000063.SZ | −10.59% | 2026-07-01 | ✗ |

历史信号构成（2021-08-05 ~ 2026-08-25）：

```
BUY  / pct_below_buy   5285 条
SELL / hard_stop_loss     4 条（最后一次 2026-01-08）
SELL / pct_above_sell     0 条
```

### 1.2 缺陷 A：退出的评估域是候选池，不是持仓

`SignalGenerator.generate()` 的循环体是 `composite_scores`，持仓分支写在**循环内部**：

```python
for ts_code, row in composite_scores.iterrows():   # ← 候选池，日均 68 只
    if ts_code not in snapshot_quotes.index: continue
    if ts_code in holding_codes:                   # ← 持仓判定在循环内
        elif pnl_pct <= -params.stop_loss_pct: ...
```

`composite_scores` 来自 `SignalService._load_generation_inputs` →
`self._repo.get_pool(trade_date)`，即 **candidate_pool**。

**后果是反向的**：跌得越狠越会掉出候选池，就越判不到止损——**越该止损的越收不到**。

### 1.3 缺陷 B：持仓保护机制存在，但调用链上没人传参

`CandidatePoolManager.compute_pool` 明写「持仓保护：holding_codes 强制入池」：

```python
pool_codes = set(sorted_codes[:self.pool_capacity])
pool_codes |= set(holding_codes)      # ← 设计上持仓强制入池
```

但四层调用**每层都默认空集**，最外层管线**根本没传**：

```
daily_pipeline.py:368  run_daily_scoring(trade_date)          ← 未传
  └ run_daily_scoring(holding_codes=frozenset())              ← 默认空
     └ _run_phase11_pipeline(holding_codes=frozenset())       ← 默认空
        └ write_candidate_pool(holding_codes=frozenset())     ← 默认空
           └ compute_pool: pool_codes |= set()                ← 保护成空操作
```

**判断**：大概率是 V1.5-G 把管线改为账户无关（G-4d-1）时的遗留——持仓保护本质是账户相关的，
与「管线账户无关」直接冲突，重构时未解决，只是让它默认成了空集。

### 1.4 缺陷 C：`pct_above_sell` 是结构性死条件

卖出条件为「市场分位 ≥ 0.70」（跌进最差 30%），但同样只在候选池上评估，而候选池是
**评分最高**的一批：

```
candidate_pool 64348 行的 composite_pct_in_market：
  最小 0.0003 | 最大 0.0286 | 满足 >= 0.70 的行数：0
```

池内最差的股票也只在市场前 2.86%，离 70% 差 24 倍。**判定集与条件集互斥，交集恒为空**——
五年 0 条不是巧合，是数学上不可能。买入 top 5% / 卖出 bottom 30% 之间是 **65 个百分点的死区**。

### 1.5 缺陷 D（机制层）：主导因子随下跌而变好

`value` 策略占 composite 权重 **0.57~0.87**（生产实测），其构成：

| 因子 | 策略内权重 | 股价下跌时 |
|---|---|---|
| PE 历史分位 | 35% | 分位下降 → **得分上升** |
| PB 历史分位 | 30% | 分位下降 → **得分上升** |
| ROE 质量 | 35% | 季度数据，短期不变 |

**65% 的权重在下跌时机械地变好。** 因此**即使把域修对，横截面评分型退出对本 composite 仍是反向的**，
最终只剩 −8% 硬止损在起作用。这是用户提出的判断，经代码核对成立。

### 1.6 另两条退出规则同样不可达

- `short_term_z_drop`（自身 z 日环比降 1.5σ）：需该股**连续两日**的 `signal_score_snapshot`，
  非池内持仓没有 → `len(snaps) < 2` → 跳过。
- `mid_term_icir_flip`：因子级 ICIR 翻负，粒度粗，会让同策略持仓同时触发。

**设计意图上这两条比 `pct_above_sell` 更合理**（看的是相对自身历史的恶化，而非横截面排名），
但被同一个域缺陷挡死。

### 1.7 更根本的一层：信号周期与持仓周期错配（P0）

> 本节由用户追问「修完退出域是不是也只能止损、无法真正让用户盈利」而补入。
> **我认为这一条比本报告其余任何一条都更接近「为什么不赚钱」。**

```
IC 面板验证的是：  因子值 → 未来 20 个交易日 的收益排序
实际持有的是：     40 ~ 72 个交易日，且无自然到期机制
```

现有持仓（截至 2026-08-28）：

| 股票 | 建仓日 | 持有日历天 | 浮亏 |
|---|---|---|---|
| 601138.SH | 2026-05-14 | **106** | −15.23% |
| 002384.SZ | 2026-05-22 | **98** | −13.14% |
| 603063.SH | 2026-06-26 | 63 | −40.67% |
| 000063.SZ | 2026-07-01 | 58 | −10.59% |

**系统买入的依据只在约 1 个月内被验证过，却把仓位拿了 2~3.5 个月。** 超出信号有效期之后，
持有的依据已经消失——既不是「因为它还好」，也不是「因为规则让我拿着」，而是**因为没有任何
机制会让它离场**。唯一的出口是 −8%（且它坏了）。

**后果**：IC 测出的那点 alpha，在持有期里衰减光了，从来没被兑现过。

**这不是退出规则修不修的问题**——任何退出规则都补不上它，它需要的是**持有期设计**：
时间止损 / 按半衰期到期复核 / 定期再平衡。

⚠️ 系统**已经在算 `half_life`**（`FactorMonitorEngine.calc_half_life`），但它只用于因子监控
告警，**没有任何一条路径把它用到持仓期限上**。又一例「算了但没用上」。

### 1.8 因此：修复退出域能得到什么、不能得到什么

**能得到（不止止损）**：
- `hard_stop_loss` 可达 → 亏损截断在 −8% 而非 −40%
- **`short_term_z_drop` / `mid_term_icir_flip` 一并解锁** —— 论点衰减退出，不等亏损发生就可能触发

**得不到**：
- 不产生任何 alpha
- 无获利了结（系统至今**没有任何盈利出口**）
- 不解决 §1.7 的周期错配
- `pct_above_sell` 仍是死条件（域修好了，5%/70% 死区还在）

**避免亏损等于保住本金，但保住本金不等于赚钱。** 退出域修复的正确定位是：
① 止损（确定性价值）；② **周期错配修复的前置**——时间止损、到期复核都要落在「退出评估域」上，
域不对则后续任何退出机制都触发不到；③ 不引入新判据，可在没有尺子时安全实施。

**不应被理解为「修完就好了」。**

## 2. 回测为何没能发现（P1）

### 2.1 保真度缺口：回测跑的是生产不存在的数据路径

```python
# 回测 engine.py:479
self._signal_engine.generate(composite, virtual_position_list, ...)
#                            ↑ 全 universe（~2700，第 g 步聚合的完整输出）

# 生产 signal_service.py:499
generator.generate(composite_scores=inputs.composite_df, ...)
#                                   ↑ get_pool() → 候选池 ~68
```

回测引擎全文 `grep pool|capacity` **零命中**——它不经过候选池。**同一个 `generate()`，
回测喂全市场、生产喂前 2.5%**。回测里持仓必在 composite 中，止损与 z_drop 正常触发，
`pct_above_sell` 也能命中（分位覆盖 0~1）；生产里三条全部落空。

**回测在结构上不可能发现 §1 的缺陷。**

### 2.2 回测在生产上几乎从未成功跑过

```
backtest_task 全部历史：6 条
  FAILED  ×5（2023-01~2026-06 各区间，即 2GB 内存墙那批）
  SUCCESS ×1（2026-04-01 ~ 2026-04-30，仅一个月）
```

即使保真度没问题，一个月的窗口也来不及让「持仓慢慢烂掉却不退出」显形。

**结论**：回测目前不是可依赖的验证工具——既不忠实于生产路径，也没有真正运行过。

## 3. 仓位管理（P1）

`PositionSizer.suggest` 是纯**固定比例法**（SDD §10.1）：`single_trade_pct=10%`，
封顶 `max_single_stock_pct=20%`，总仓 `max_total_pct=80%` × 市场系数。
代码内 `grep kelly|volatility.*siz|risk_parity` **零命中**。

后果两条：

1. **信心度被抹平**：`composite_z=+3.5` 的极强信号与 `+1.6` 的边缘信号拿同样仓位，
   评分的区分度在下单环节丢失；
2. **风险贡献失控**：年化波动 60% 与 15% 的标的同样 10% 仓位，单笔风险贡献相差约 4 倍。

**判断**：评分做得再准，若仓位不区分，收益也留不住。「分数凯利」已登记 roadmap V1.5-D，未实施。

## 4. 风控（P2）

`RiskChecker.check` 覆盖三项：单股集中度（BLOCK）、行业集中度（BLOCK）、账户回撤（WARN）。

**缺相关性聚集检查**：四个策略可能同时指向同一类标的（如都选中低估值周期股），
行业标签不同但实际风险敞口高度重合，行业上限挡不住。

---

## 5. 闭环缺失：系统不知道自己的建议对不对（P0）

```
signal 状态分布：EXPIRED 5189 / NEW 100 / ACTED 0
trade_record：106 笔真实成交（2026-02-09 ~ 2026-07-03）
```

**没有一条信号被标记 ACTED**，而账户里有 106 笔真实成交——信号与实际交易之间**没有关联记录**。
`signal` 表也无任何事后收益字段。

因此系统无从回答：用户实际执行了哪些建议？被执行的建议事后赚钱了吗？哪个策略的建议更好？

**判断**：对一个以「帮用户赚钱」为目标的系统，这条闭环不通意味着**既无法从历史中学习，
也无法证明自己有用**。重要性仅次于退出缺陷。

---

## 6. 换手与成本从未度量（P2）

IC 面板不含换手；生产不记录换手；回测没跑过。而成本是确定的负收益
（双向佣金 0.075% + 印花税 0.05% + 滑点 0.1%）。**分子（预测力）在测，分母（成本）没测。**

## 9. 建议动作

### 9.0 真正的盈利杠杆（按判断排序）

上一节之前的内容多为**缺陷**；本小节回答「那什么能让用户赚钱」。

1. **持有期与信号周期对齐**（§1.7）——现在完全缺失，且系统已经在算 `half_life` 却没用上。
   若因子预测视界是 20 个交易日，就该有到期复核 / 时间止损 / 定期再平衡，
   让 alpha 在它还在的时候兑现。**我判断这是最大的一块。**
2. **半数策略的 IC 是负的**——off 组基线（2024-07~2026-07，497 交易日）：

   | 策略 | UPTREND | DOWNTREND | OSCILLATION |
   |---|---|---|---|
   | value | **+0.044** | +0.009 | **+0.051** |
   | mean_reversion | +0.010 | **+0.057** | **+0.059** |
   | trend | +0.008 | **−0.058** | **−0.034** |
   | momentum | −0.010 | **−0.070** | **−0.070** |

   value 与 mean_reversion 在扛，trend 与 momentum 在拖。ICIR 机制已把 momentum 权重压到 0
   （机制在工作），但 trend 在 OSCILLATION（22/37 个月）仍为 −0.034。
   **把负 IC 策略的权重真正清零、或搞清它们为何为负，比新增第五第六个策略更能提高有效性。**
3. **仓位按信心度 / 波动率标定**——IC ≈ 0.05 意味着排序信息不强，
   「把更多钱放在更强的信号上」是把这点信息变现的主要方式；现在全部 10%，等于扔掉评分区分度。
4. **成本与换手**——分母从未度量。IC 0.05 的策略，换手稍高就可能被 0.175% 单边成本吃掉。

> ⚠️ 第 1、3 项都需要先有评估手段（V1.5-K + 事件研究 + 持有期分析）。**先有尺子，再改规则。**
> 第 2 项可用现有 IC 面板直接推进，是当下证据最充分的一条。

### 9.1 缺陷修复（优先级）

1. **P0-退出**：① 止损改为**遍历持仓**（`pnl_pct` 来自 `position` 表，不依赖评分）；
   ② 卖出评估域独立为「持仓 ∪ 关注列表」并持久化其评分行（全 universe 评分当日已算，
   只是没存，**不增加算力**）；③ `pct_above_sell` 的 5%/70% 死区改窄带或废弃；
   ④ 固定 8% 改**波动率标定**；⑤ 补移动止盈与时间止损（现无任何盈利出口）；
   ⑥ **按买入理由决定退出理由**（动量买入→动量破位退出；价值买入→质量恶化退出而非看价格）。
2. **P0-闭环**：建立 signal ↔ trade_record 关联 + 事后收益归因。
3. **P1-仓位**：信心度 / 波动率标定（分数凯利，V1.5-D）。
4. **P1-回测**：消除保真度缺口（生产与回测必须共用同一取数路径），并让它真正跑起来。
5. **P2**：相关性聚集风控、换手与成本度量。

> 退出规则的改动**目前无法验证**——IC 面板测的是横截面预测力，评价不了退出时机。
> 需要事件研究 / 持有期分析，与 V1.5-K 并做。**先有尺子，再改规则。**

## 10. 执行次序（2026-08-28 用户拍板）

原计划是「C1 面板判定 → C1 上生产 → 观察 3 交易日」。体检后**把 C1 部署往后挪一位**：

| 序 | 动作 |
|---|---|
| 1 | C1 面板判定 + 回写设计文档 §3.3（不改代码） |
| 2 | **P0 退出修复**（止血） |
| 3 | C1 上生产 + 观察 ≥3 交易日 |
| 4 | V1.5-K 验证方法学（可与 3 并行） |

**理由**：C1 改的是「买什么」，退出缺陷决定「能不能卖」。**在退出坏掉的情况下部署一个改变
选股的变更，等于往一个没有出口的容器里继续加东西**——买得再准，卖不掉就兑现不了，
且更多持仓意味着更多标的暴露在该缺陷下。C1 代码已交付、面板结论也会拿到，晚几天上线不损失什么；
退出缺陷每多一天就多一天暴露。

### ⚠️ 第 2 步内部还要再分两类，判据不同

| 类别 | 例子 | 能否在「没有尺子」时动 |
|---|---|---|
| **纠正域错误** | 止损改为遍历持仓；卖出域独立持久化；`holding_codes` 传参 | ✅ **可以**——这是修正一个明显的作用域错误，不引入新判据。止损本就不该依赖评分 |
| **更改退出判据** | 固定 8% 改波动率标定；论点失效退出；窄带阈值 | ❌ **不应该**——这是引入新的预测性主张，必须先有评估手段（V1.5-K + 事件研究），否则只是凭直觉换一组参数 |

**不要把两类混进同一批。** 第一类是止血，第二类是治疗方案，后者需要先有诊断工具。
