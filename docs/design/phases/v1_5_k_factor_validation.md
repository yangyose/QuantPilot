## 1. 概述

### 1.1 背景：这把尺子量错过一次，而所有后续决策都要用它

C1-2 判定期实测暴露：现行「日级 Rank IC + 月聚合 t 检验」有系统性弱点，其中**重叠窗口
高估显著性**已实际产生过错误结论——朴素 t 把 momentum 的 **UPTREND 与 DOWNTREND
双双判为「高度显著」**，改用 Newey-West（HAC, Bartlett, lag=20）后两者双双退位。
有效样本仅名义的 **8~12%**。

引用 `v1_5_c §3.3` 权威表（**均为全程 25/25 收敛值**，写成「状态 + 数值 + 是否收敛」
三元组以防脱表后被简化）：

| 状态 | 天数 | t_朴素 | **t_HAC20** | 定性 |
|---|---|---|---|---|
| OSCILLATION（主导） | 323（65%） | 0.65 | **0.19** | 噪声量级 |
| UPTREND | 104 | 4.91 | **1.72** | 不显著 |
| DOWNTREND | 70 | 6.83 | **2.32** | 名义显著，但仅一个下跌周期、非重叠样本 4 个 |

**三状态全列**（不摘录）：只列其中一个会让「高估不是个别状态的偶然」这一立项理由变弱；
而列全了还能挡住反向的过度概括——**OSCILLATION 的朴素 t 仅 0.65，它本就不显著**，
说成「三状态全部高度显著」是错的（`v1_5_c §3.3` 与本文 v0.2 都犯过，v0.4 双向订正）。

⚠️ **不要引用中途快照**：跑到 18/25 时 OSCILLATION 为 `+0.0033 / t_HAC 1.33`，全程收敛
至 `+0.0007 / 0.19`——效应随样本补全向 0 收敛。`v1_5_c §3.3` 已明写「中途数字不可当
结论」，本文 v0.2 曾误把该快照当既定事实复述，v0.3 订正。

而 C2 / C3 / C4 及后续所有因子决策都要用这把尺子。体检报告 §9.1 的定性是
**先有尺子，再改规则**——D-EXIT 与 E-LOOP 同样排在本主题之后，因为 IC 面板测的是
横截面预测力，**评价不了退出时机**。

2026-08-31 C1+P0 上生产后暴露第五处缺口：想验证 C1-3 是否生效，发现
**痕迹根本不存在**——生产从未记录因子级指标（K-6）。

## 2. 设计定案

### 2.1 持久化结构：新表 `factor_panel_stat`

**⚠️ 较 v0.1 推荐有一处修正。** v0.1 推荐「K-6 走现表 `factor_ic_window_state`
（用新 `row_type`）、其余入新表」，理由是现表的 `factor` 维度一直空着（所有行
`factor` == 策略名），形状完美匹配且零 migration。

**展开 K-3 时发现该切分点是错的**：K-3 要求同一因子在 4 个 horizon 上都出 IC。
若按 v0.1 切分，同一个「因子级 IC」会**按 horizon 劈成两处**——h=20 在现表、
h=5/10/40 在新表。这种切分没有语义依据，只会让后续分析每次都要 union，
且两处口径必然随时间漂移。

**修正后的切分依据改为「运行时 vs 研究」**：

| | 表 | 内容 | 生命周期 |
|---|---|---|---|
| 运行时 | `factor_ic_window_state`（**不动**）| 策略级 IC @ h=20 + ICIR 聚合行 | 每日增量，喂 ICIR 决定实盘权重 |
| 研究 | `factor_panel_stat`（**新**）| K-2~K-6 全部统计量 | 整批重跑、可整批丢弃重来 |

这样现表**一个字节都不用改**，三个读取方（`get_ic_daily_window` 喂 ICIR /
`get_monthly_quality_ic_series` / `get_existing_daily_ic_dates` 断点续传）零风险。
其中 `get_existing_daily_ic_dates` **不按 factor 过滤**，只看 `row_type` + 日期——
按 v0.1 方案往现表塞因子行，一旦 `row_type` 用错就会让续传误判「该日已回填」而静默跳过。

```sql
CREATE TABLE factor_panel_stat (
    id           BIGSERIAL PRIMARY KEY,
    panel_run    VARCHAR(64)  NOT NULL,  -- 重跑批次（配置+日期），令多次重跑并存可比
    trade_date   DATE         NOT NULL,
    strategy     VARCHAR(32)  NOT NULL,
    factor       VARCHAR(64)  NOT NULL,  -- 因子名；组合级指标填 '__portfolio__'
    stage        VARCHAR(16)  NOT NULL,  -- 'raw' | 'z'（§2.2）；组合级填 'n/a'
    state        VARCHAR(16)  NOT NULL,  -- 市场状态
    horizon      SMALLINT     NOT NULL,  -- 前向交易日 5/10/20/40；无前向概念填 0
    metric       VARCHAR(32)  NOT NULL,  -- 见下方枚举
    bucket       SMALLINT     NOT NULL DEFAULT -1,  -- 十分位 1..10；不适用填 -1
    value        NUMERIC(12,6),
    sample_size  INTEGER      NOT NULL,
    created_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
    CONSTRAINT uq_factor_panel_stat UNIQUE
        (panel_run, trade_date, strategy, factor, stage, state, horizon, metric, bucket)
);
```

`metric` 枚举：`ic` / `valid_ratio`（K-6 有效非 NaN 率）/ `decile_fwd_return`（K-2）/
`top5_excess`（K-2）/ `turnover_jaccard`（K-4）/ `cost_drag`（K-5）。

**`bucket` 必须 `NOT NULL DEFAULT -1`，不可用 NULL 表示「不适用」**：PostgreSQL 的
UNIQUE 约束把 NULL 视为**互不相等**，可空的 bucket 会让唯一键形同虚设、静默写入重复行。
与 C0-7 唯一约束撞车同一族。

采用长表（tidy）形态而非宽表：本表是**整批重跑产出、供分析脚本消费**的研究数据，
指标会随方法学演进增减，宽表每加一个指标就要一次 migration。

### 2.2 因子级截取层：`raw` + `z` 双版

`Scorer.aggregate` 对每个因子已完整走 `raw → winsorize → neutralize → zscore`，
四个中间量都是现成的（Phase 12 血缘已在落 winsorized / neutralized）。本主题取两端：

| stage | 含义 |
|---|---|
| `raw` | 因子的**固有**预测力，未经五步管线加工 |
| `z` | **系统实际使用的那一版**（进 composite 的就是它）|

取两版的真正理由：**两者之差 = 五步管线（Winsorize + 行业/市值/Beta 中性化 +
正交化）到底提升还是损耗了预测力**——这套管线自 Phase 11 上线至今从未被量过。
行数翻倍但基数极小（现运行时表全量仅 5324 行）。

> 这一项略超 roadmap 对 K-FACTOR 的最小读法（最小读法只要求落一版），
> 采纳理由是它是本次重跑中**唯一能近乎免费拿到的新信息**。

### 2.3 holdout：固定近端 12 个月 + 一次性解锁

用户 2026-09-01 拍板方案 D（近端留出 + 明确解锁条件）。

| 区间 | 范围 | 用途 |
|---|---|---|
| 开发集 | `2021-05-13 ~ 2025-07-31`（约 1010 交易日）| 因子研究、参数选择、反复试 |
| **holdout** | `2025-08-01 ~ 2026-07-31`（约 240 交易日）| **改造期不看** |
| 实盘期 | `2026-08-01` 之后 | 只用于上线后观察，**永不用于因子选择** |

**边界固定，不随时间滚动**——滚动 holdout 会让「今天的 holdout」变成「明天的开发集」，
看过就无法假装没看过。

**解锁条件**：某个因子决策**定案时**解锁一次；解锁后该决策即冻结，
不得依据 holdout 结果回头调参（那等于把 holdout 变成第二个开发集）。

**⚠️ 必须如实记录它的局限**：20 日前向窗口下，240 个交易日的 holdout 只有约
**12 个非重叠观测**。它的作用是**纪律性的，不是统计功效**——
它能证伪一个被强烈声称的效应，**不能确认一个弱效应**。
任何「holdout 上也是正的所以有效」的论证在 12 个观测上都不成立，禁止如此使用。

### 2.4 成本口径：复用回测参数

复用 `config_defaults`：佣金 `0.025%` / 印花税 `0.05%` / 滑点 `0.1%`。

已核实三者**真被消费**，不属 F-SI 那 12 个零引用字段。复核口径（记口径而非记数字——
数字随代码漂移，口径不会）：

```bash
cd backend && for k in commission_rate stamp_tax_rate slippage_rate; do
  echo "$k = $(grep -rn "$k" --include=*.py src/ | grep -v __pycache__ | wc -l)"
done
```

2026-09-01 实测 `9 / 8 / 13`（含 schema 与注释行）。**判据是「非零」而不是具体数值**——
F-SI 那族缺陷的指纹是**零引用**，只要非零就说明配置真被读到；
但注意 §4.4 记的假阴性风险：同名标识符会让按名字检索虚高，故非零后仍需看一眼命中位置。

K 另定一套的话，同一个「成本」会在回测与因子验证里得出不同结论——
**两处口径分叉**正是本仓反复付过代价的形态（红线②、`BACKTEST_ENABLED`）。

### 2.5 重跑范围：全 5y、单配置、一次产出

| 项 | 定案 |
|---|---|
| 窗口 | **全 5y**（`2021-05-13 ~ 2026-07-31`，约 1250 交易日）|
| 配置 | **单组**（生产当前 = C1 on）。off/on 对比已在 C1 收口时完成，不重来 |
| ETA | 约 **13h**（C1 面板实测**单组** 497 交易日 / 5h10m → `1250/497 × 5.17h ≈ 13h`）|
| 执行机 | **第二台 24h 算力机**，`docker-compose.backtest-local.yml` + DB:5434，detached |

ETA 的两个方向修正（相互抵消，故仍按 13h 备料，**实际以第一个 chunk 的实测速率为准**）：
**偏短** ← 面板窗口（2024-07~2026-07）是近端，universe 最大；回溯到 2021 年 universe 更小、
每日更快。off 组内部实测即随 universe 单调上行：**首日 32s/交易日**（universe 2513）
→ **2025 年段 40~42s/交易日**（universe 2710+），出处 memory `c1_panel_comparison_runbook`
「本机实测参数」节；全程墙钟均值 `5h10m / 497 ≈ 37s/交易日`，出处 `v1_5_c §3.3` v0.14
——**37s 落在 32~42s 区间内部**，与该窗口内 universe 持续增长的曲线一致（它是这段的加权
平均，不需要用调度开销解释）。独立验算：`32~42s × 1250 天 = 11.1~14.6h`，13h 居中。**偏长** ← K-6 因子级 IC 与 K-2 十分位阶梯
是新增计算量，但只是已算出的矩阵上做相关/分组，不重跑评分，增量应远小于主成本。

⚠️ v0.2 此处误写 **25h**——那是 off+on **两组合计** 10h 的外推值，而本次是**单组**。

不用面板窗口（497 日）的理由：K 的立项前提就是「有效样本仅名义的 8~12%」——
497 日修正后约 50 个有效观测，**做十分位阶梯太薄**。用一个样本不足的窗口去修
样本不足的问题说不通。

**红线**：重跑调用全 universe 评分路径，**只能在算力机跑**（CLAUDE.md §6 运维红线①，

## 3. 测试计划与收尾门槛

**本主题的测试有一个特殊性，实施时必须时刻记住**：它产出的是「用来判断别的东西
对不对」的度量——**它自己错了，没有更上层的尺子能发现**。因子有没有效，最终就是靠
这些数字回答的；数字错了，错误会一路传导到实盘选股。

因此下列四条是硬门槛：

1. **对照解析解** —— HAC 估计量须在构造数据上与已知解析解比对（如已知自相关结构的
   AR(1) 序列，其 Newey-West 方差有闭式）。**只测「不抛异常」不算数**。
2. **「改输入 → 结果必须变」** —— 重叠度改变时，有效样本数与 t 值必须相应变化。
   这是 §4.11 判定「参数是否真被消费」的标准形态，本主题尤其适用：
   HAC 的 `lag` 参数传错名同样会静默落进 `**kwargs`（pandas_ta 那条的同构风险）。
3. **退化输入行为须显式定义并断言** —— 横截面无方差 / 样本不足 / 全 NaN /
   某 horizon 前向窗口不完整。现 `compute_daily_ic` 的做法是**跳过不写占位行**，
   新指标须与之一致，否则同一天在不同 metric 上会出现「有的有行有的没行」。
4. **⛔ 不得用本主题的产出验证本主题的正确性**（自证）。
